# AeroDynamic Wiki

一个用 LLM 维护的论文知识库，以**气动透镜 (Aerodynamic Lens)** 领域为例。

---

## 简介

本知识库基于 [llm-wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) 的 Karpathy 方法——用 LLM 增量构建并持续维护一份结构化、互链的领域 wiki,而不是每次提问都让 LLM 从原始文档现取现答。

特化场景：**学术论文为主的领域知识库**。当前主题是气动透镜与纳米颗粒束流（Aerodynamic Lens / Particle Beam）。

与传统 RAG 的区别:**wiki 是一个持续累积的资产**。每读一篇新论文,LLM 不仅写一份简记,还会更新相关概念页、刷新实体页、补对比页、调整主题 MOC——整个 wiki 越读越富。

## 文件夹结构

```
AeroDynamic/
├── CLAUDE.md       # 规则手册 (LLM 维护行为的 schema)
├── README.md       # 本文件
├── index.md        # 总目录 (手工维护 wiki + Dataview 自动列 raw)
├── log.md          # 时间线日志 (ingest / query / lint)
│
├── raw/            # 源资料 (immutable, 用户上传)
│   ├── 论文/        # 学术论文 (主体)
│   ├── 书籍/        # 书籍 / 长文综述
│   ├── 媒体/        # 视频 / 音频 / 播客 (含转录)
│   ├── 网页/        # 网页剪藏
│   ├── 笔记/        # 用户自己的笔记 / 思考
│   └── assets/     # 图片附件
│
└── wiki/           # LLM 维护的提炼层
    ├── 主题/        # MOC 导航中枢
    ├── 概念/        # 单点抽象概念
    ├── 实体/        # 人 / 公司 / 仪器 / 软件
    ├── 摘要/        # 每篇 raw 一份提炼
    ├── 对比/        # 跨源对比分析
    └── 问答/        # 探索性问答沉淀
```

## 如何使用

### 1. 添加新资料(Ingest)
把新论文 / 笔记 / 网页放进 `raw/` 对应子文件夹,告诉 LLM "更新知识库" 或 "ingest"。LLM 会自动:
- 读取并讨论关键要点
- 在 `wiki/摘要/` 写简记
- 扫描已有摘要,触发新概念 / 实体 / 对比 / 主题
- 同步更新 `index.md` 与 `log.md`

一次 ingest 可能涉及 10-15 个页面更新。

### 2. 提问(Query)
对 wiki 提问。LLM 会先读 `index.md` 定位,再深入相关 wiki 页面综合作答。**有价值的回答可以请求归档为对比 / 问答页**,这样探索本身也会沉淀进 wiki。

### 3. 健康检查(Lint)
偶尔请 LLM 做一次全库 lint,扫描:
- 矛盾断言
- 孤儿页面
- 应升格但还没建的概念 / 实体
- 反向虚假升格（sources 不独立）
- 链接 / 索引漂移

### 4. 浏览
用 Obsidian 打开整个文件夹,从 `index.md` 或 `主题/气动透镜与纳米颗粒束.md` 进入,跟着 wiki-link 自由浏览。graph view 可以看到整体结构。

## 模型选择建议

LLM 后端选 Claude(Sonnet 或 Opus),按任务规模与复杂度切换：

| 场景                                | 建议模型       |
| --------------------------------- | ---------- |
| 少量论文 / 笔记 添加（1–9 篇）、简单询问          | **Sonnet** |
| 大批量添加（≥10 篇）、学位论文深读               | **Opus**   |
| 撰写对比页 / 新主题 MOC、全库 lint、schema 修订 | **Opus**   |
| 跨学派 / 多页面综合 query                 | **Opus**   |

**原则**:任务**多步且互相依赖**(一处错传播到多个文件) 或 **综合性强**(要识别集群、对比、张力) 用 Opus；**局部独立、可逐处验证**的编辑用 Sonnet。

## 常规动作建议

- **首次使用**可以告诉大模型：“根据知识库规则创建文件夹结构”
- **上传新资料后,告诉 LLM "更新知识库"** —— 它会自动 ingest、扫触发、改 index / log,不需要你逐步指挥
- **参与 §3 升格决策** —— LLM 触发新概念 / 实体 / 对比时通常会先问你；可顺着接受、要求等更多 sources、或要求换更窄/更宽的定义
- **主动请求建主题 MOC 或对比页** —— LLM 不会自动建主题；当你觉得某个集群已成形或某组论文有张力,直接要求"建一个主题/对比"
- **查 LLM 改动的结果** —— Obsidian 的 graph view 看新连接、点新建的 wiki-link、读新摘要;不满意就提出修订
- **自己的笔记放 `raw/笔记/`** —— LLM 会和论文一样按 §5.5 简记处理,纳入相同的触发机制
- **偶尔请 LLM 做 lint** —— 直接说"做一次全库健康检查";它会扫矛盾、孤儿、虚假升格、链接漂移
- **session 起手提醒重读 CLAUDE.md** —— 新会话首次互动时,即使 CLAUDE.md 在上下文里,显式说一句"先重读 CLAUDE.md" 能让 LLM 行为更稳定
